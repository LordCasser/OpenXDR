## 范围与顺序

沿用 OpenXDR 名称，定位为 AI 原生检测、调查与响应平台。本轮不改名、不部署，不修改正在开发的文档导入。

1. **采集可靠性**：本地有界持久缓存；采集与连接生命周期分离；注册身份与缓存绑定；批次收到持久接收确认才删除；重传稳定事件 ID；服务端幂等；明确展示采集降级、队列积压和丢失。包含进程重启、断网、ACK 丢失、磁盘满、文件损坏的验证。
2. **跨事件检测**：支持有明确事件时间语义的计数与序列规则，按组及实体隔离；重投、乱序、迟到、进程重启不重复制造告警；配套攻击与良性回放，不用单事件条件冒充序列。
3. **身份关联**：接入实际使用的身份来源，将账号、登录会话和设备关联；先建立可验证的归一化契约与测试，真实来源配置及验收另行记录，不能用猜测的身份关系补图。
4. **AI 响应闭环**：结构化前置证据、审批、执行状态、结果复核、失败处理与审计；超时不等于执行失败，重试前核对副作用。建立调查正确性和成本评测。

## 第一批实现与验证（2026-10-18）

- `agent/src/spool.rs`：Protobuf 批次、SHA-256 完整性校验、写临时文件并同步后替换、独占进程锁、有界容量、不删除未确认批次。损坏文件保留并报错。
- `agent/src/delivery.rs`：最多 128 条或约 3 MiB 一批，低流量每秒刷盘；上传关闭发送流并等待完整 ACK；失败保留整批。采集缓存不依赖网络连接。
- 注册身份按 server 地址和主机名分目录缓存；成功注册过的主机离线重启可继续采集。首次注册前没有服务器身份，不声称能离线纳管。服务端变更 agent ID 时停止发送并保留旧数据。
- 重连获取不同采集配置时，关闭旧采集入口并排空已接收事件，然后保存新配置并重启采集；排空期间上传继续工作。
- `OPENXDR_STATE_DIR`：Linux 默认 `/var/lib/openxdr/agent`，Windows 默认 `%ProgramData%\OpenXDR\state`。Linux scope 目录 0700、文件 0600；Windows 继承目录 ACL，需实机核对服务账号权限。
- `OPENXDR_SPOOL_MAX_BYTES`：默认 256 MiB，至少 4 MiB；另设 8192 个批次上限。容量统计是文件内容大小，不是文件系统实际分配空间。
- 容量耗尽时保留待写批次并重试，内存采集队列仍可能溢出；尚未刷盘的批次在进程崩溃时可能丢失。此方案不承诺断电零丢失。
- 本地 gRPC 测试覆盖接收完毕后 ACK 丢失、重新打开缓存、逐字节一致重传及成功后删除；PostgreSQL 集成测试覆盖真实接入处理器的事件/告警幂等。测试使用独立临时数据库，结束已删除。
- Linux 单测 109 项通过；Linux 与 Windows GNU 交叉 clippy 通过。Windows 文件锁/替换只经过编译，未实机运行。

## 第五批实现与验证（2026-10-18）

- Linux SIGTERM/SIGINT、Windows Ctrl+C/Ctrl+Break 触发关闭采集入口和落盘排空，覆盖注册等待、重连间隔、在线传输及升级下载。排空最多等待 30 秒；在线时继续补传释放容量，离线时保留磁盘批次供重启后补传。不等待所有批次上传成功。
