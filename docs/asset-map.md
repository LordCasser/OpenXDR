# 资产图谱与攻击面

主机纳管后，平台自动回答两个问题：

- **运维**：这台机器是干什么的、有多重要、依赖谁、被谁依赖（资产图谱）
- **安全**：哪些服务暴露在哪一层、谁在访问、哪些机器还没纳管（攻击面）

事实全部来自确定性采集，AI 只做解读：AI 标的角色和重要程度可以人工修改并锁定，
暴露面与盲区不经过模型，按规则计算。

实现位置：agent `collector/inventory*.rs`、`collector/cloud.rs`；server `internal/assetmap`、
`internal/api/assetmap.go`；前端「资产 → 资产图谱 / 攻击面」与资产详情页的「资产画像」。

## 数据来源

| 事实 | 来源 | 说明 |
|---|---|---|
| 监听端口与属主进程 | agent 设备清单（class 5001） | Linux 读 `/proc/net/{tcp,tcp6,udp,udp6}`，Windows 读 IP Helper 监听表；每 60 秒比对，变化或满 6 小时才上报 |
| 云环境 | agent 设备清单（class 5001） | 启动时探测一次 AWS / Azure / GCP / 阿里云 / 腾讯云元数据服务；拿不准就不报 |
| 依赖边 | 网络事件（class 4001） | agent 出站连接（Linux 需 eBPF 构建，Windows 走 ETW）与 sensor 会话 |
| 见过的程序 | UEBA 基线 | 只给 AI 标注做参考 |

server 侧由集群单活的 `assetmap` 任务增量扫描已落库的 4001 / 5001 事件（游标存在 `settings`
表的 `assetmap.cursor`），把清单物化到资产上、把连接聚合成依赖边（`asset_links`）。
首次启用回补最近 7 天的连接；30 天没再出现的边自动删除。

依赖边只记 (源地址, 目的地址, 端口, 协议, 发起进程)，对端是哪台资产在**读取时**按 IP 解析：
发现的机器后来纳管了，图谱自动连上。不算依赖的连接：回环、组播、链路本地、自己连自己，
以及宿主机里容器之间的通信（源地址不是本机登记的地址、目的与源同在一个私网段）。

UDP 只收端口低于系统临时端口范围的未连接套接字（Linux 读 `ip_local_port_range`，
Windows 按 49152），客户端随机端口不算监听。`/proc/net/*` 只反映 agent 所在网络命名空间：
agent 跑在容器里时看到的是容器自己的监听。

## 区域与暴露级别

区域判定优先级：组管理员手工指派 > 组内网段（最长前缀）> 云元数据 > 按 IP 公私。

| 区域类型 | 含义 |
|---|---|
| `internal` 内网 | 无公网地址的内网主机（CGNAT 100.64/10、IPv6 ULA 也算内网） |
| `dmz` 隔离区 | 组管理员定义的网段 |
| `external` 公网区 | 带公网地址，或组管理员定义的公网网段 |
| `cloud` 云上 | agent 读到了云厂商元数据 |

暴露级别：公网区、带公网 IP、云上有公网地址都算**公网可达**；DMZ 区域算**隔离区可达**；
其余**仅内网**。绑在具体公网地址上的服务直接算公网可达，回环监听不进攻击面。

区域在「攻击面 → 网段与区域」里由组 admin 维护，网段统一规范成网络地址写法；
删除区域时指派到它的资产回到自动划分。

## 攻击面

每台资产的每个（协议, 端口）算一条暴露面，同时绑在 `0.0.0.0` 与 `::` 的双栈监听合成一条；回环监听不算。
风险分 = 暴露级别 × 端口风险 × 重要程度：

| 因子 | 取值 |
|---|---|
| 暴露级别 | 公网 20 / 隔离区 6 / 内网 2 |
| 端口风险 | 高 3（远程管理、数据库、容器编排、文件共享等）/ 中 2 / 低 1，按端口推测，见 `assetmap/ports.go` |
| 重要程度 | AI 标注或人工指定的 1-5，未标注按 3 |

每条暴露面附带观测到的访问来源；来源里出现公网地址标「有公网访问」——这是实际被外部
访问的证据，不是推测。

**盲区**：与本组资产有往来、却没有纳管的内网地址，分两个方向列出：本组连过它的哪些端口、
它访问过本组的哪些服务。其他组的已纳管资产不算盲区，也不露主机名。

还没上报设备清单的资产（旧版 agent 或刚接入）会在攻击面顶部点名：它们的暴露面是空的，
不代表没有暴露。

## AI 标注

模型看到的只是事实：主机名、系统、地址、区域、云环境、监听端口、内网依赖与被依赖、
公网目的地址的个数、见过的程序。输出角色、功能说明、重要程度（1-5）、依据和对端关系说明。
输出不可信：只取第一个 JSON 对象，逐字段校验与截断；关系说明只保留事实里出现过的对端。

触发时机：

- **入库**：新资产的设备清单到了就标注（清单迟迟不到，最多等 10 分钟后凭已有事实标注）
- **变动**：每 10 分钟重算一次事实指纹（监听端口、内网依赖、区域、云环境），变了就重标，
  同一台至少间隔 1 小时；程序清单与公网目的地址变化频繁，不进指纹
- **定时**：超过 `ASSET_ANNOTATE_REFRESH_HOURS`（默认 24）没标过的重标，0 表示只在变化时标
- **人工**：资产画像里点「重新标注」

标注调用关掉 GLM 模板里的隐式思考（与 Pi 会话同一判定），输出上限 2048 token：隐式思考不返回却占输出，
实测同一台主机耗时在 17 秒到超过 120 秒之间波动，后台批量调用会反复超时。

人工改过的角色、功能说明、重要程度记入 `locked_fields`，AI 不再覆盖；「交还 AI」解锁并立即
重新标注。每轮最多标 3 台；失败的资产 10 分钟内不再重试。未配置 `AI_MODEL` 时不做标注，
图谱与攻击面照常可用。

AI 助手的对话上下文里，组内资产清单也带上了角色、重要程度、区域和暴露级别。

## 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/asset-map?groupId=` | 组 viewer | 节点（本组资产 / 未纳管地址 / 别组资产 / 互联网）与有向边 |
| GET | `/api/attack-surface?groupId=` | 组 viewer | 汇总、暴露面（按风险分降序）、盲区 |
| GET | `/api/zones?groupId=` | 组 viewer | 区域定义 |
| POST | `/api/zones` | 组 admin | `{groupId,name,kind,cidrs}`；同名 409 |
| PUT / DELETE | `/api/zones/{id}` | 组 admin | 修改 / 删除 |
| GET | `/api/assets/{id}/profile` | 组 viewer | 资产画像：区域、暴露、云、监听、依赖、标注 |
| PUT | `/api/assets/{id}/profile` | 组 analyst | `{role?,summary?,criticality?,unlock?:[]}`，改即锁定 |
| PUT | `/api/assets/{id}/zone` | 组 admin | `{zoneId}`，null 回到自动划分；只能指派本组区域 |
| POST | `/api/assets/{id}/annotate` | 组 analyst | 请求重新标注；未配置模型返回 503 |

区域增删改、标注修改、区域指派都写审计日志。

## 配置

| 位置 | 项 | 默认 | 说明 |
|---|---|---|---|
| server 环境变量 | `ASSET_ANNOTATE_REFRESH_HOURS` | `24` | 定时重新标注周期，0 只在变化时标注 |
| server 环境变量 | `AI_MODEL` 等 | — | 与旧 triage 共用模型配置 |
| 主机采集配置 | `collectInventory` | `true` | 关掉后该主机不上报监听端口与云环境 |

## 已知限制

- Linux agent 只有 eBPF 构建才上报出站连接；netlink / 轮询模式下依赖边只能来自 sensor
- 端口到服务的映射是推测，不做协议识别
- 「公网可达」按地址与区域判定，没有从外部实际探测可达性
- 云元数据探测只在 agent 启动时做一次；实例更换公网地址需要重启 agent 才会更新
- Windows 监听表与云探测只经过交叉编译与单元测试，尚未实机验证
