# 实验性时序规则

此目录独立于单事件 `rules/`，默认不启用。配置 `TEMPORAL_RULES_PATH` 指向本目录才能加载，
容器需要只读挂载；同时保持 `RULES_PATH` 指向配套基础规则。基础规则和时序规则必须成套发布。

- `linux-auth-burst.yml`：同组同主机 5 分钟内至少 5 次 Linux 失败认证。当前实体为主机，
  不按账号或源 IP 分组；不同用户的失败也会累计。它是集中失败线索，不能直接断言账号遭到暴力破解。
- `linux-account-auth-burst.yml`：同组同账号 10 分钟内至少 5 次 Linux 失败认证，`group_by: account`，
  跨同组多台主机累计（不要求至少两台不同主机，单机 5 次失败会同时命中上一条）。账号取事件 `username` 列，
  去首尾空白、转小写后比较，不做域前缀/UPN 互认；没有用户名的失败不计入，记为 `no_account` 缺口。
  不同组的同名账号互不累计；资产换组后其此前的失败不再计入。它是账号被集中尝试的线索，不能断言来源或成败。
- `linux-download-sensitive-file.yml`：同组同主机 10 分钟内先出现下载内容管道进 shell，
  再出现敏感文件变更。两步要求严格递增时间；只证明主机级时间关联，不证明同进程因果关系。
  正常运维也可能触发，需要结合原始证据复核。

规则字段见 [时序检测实现约定](../docs/temporal-detection.md#规则格式)，`group_by` 可选 `asset`（默认）或 `account`，未知取值拒绝加载。
生产按不可变版本目录发布时，每个版本目录需带 `SHA256SUMS`，见同文档「不可变版本目录发布」。

基础规则仍会各自产生单事件告警。时序级别为 high，不自动触发任何额外处置。
单元回放与数据库持久回放见 `validation/temporal/README.md`；尚未做生产误报率评估。
上线前用 `cmd/backtest` 的时序模式在生产只读副本上回测命中量，见 [时序检测 · 回测](../docs/temporal-detection.md#回测)。
